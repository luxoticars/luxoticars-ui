# Dialog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a native-`<dialog>` component (`lightbox`, `confirm`, `panel`) in both package APIs — Astro (`Dialog`, `DialogTrigger`) and HTML (`createDialog`, `createDialogTrigger`) — sharing one stylesheet, one option resolver and one runtime script.

**Architecture:** One BEM stylesheet (`src/styles/dialog.css`) styles both APIs, as `logo.css` does. One internal resolver (`src/utils/dialog.js`) validates options and derives classes, ids, role and `closedby`, so the Astro component and the string builder cannot drift. Opening and closing use invoker commands (`command`/`commandfor`), with no JS. A small idempotent script (`src/scripts/dialog.js`) resets stale `returnValue`s and fills in backdrop-dismiss for Safari.

**Tech Stack:** Astro 7.3.2, plain JS + hand-written `.d.ts`, CSS (`@starting-style`, `transition-behavior: allow-discrete`, `:modal`, `:has()`, `dvh`), Storybook 10 (`@storybook-astro/framework`, static render mode), `node:test` for builder unit tests, `playwright-core` (scratchpad only) driving Chrome and Playwright WebKit for DOM tests.

**Spec:** `docs/superpowers/specs/2026-10-13-dialog-design.md`. Read it before starting any task.

### Deliberate deviations from the spec

The executor implements these. They are listed so a reviewer does not "fix" them back.

1. **Token order is `--lux-*` first, daisyUI name second.** Tailwind's `@theme` declares `--color-base-100: var(--lux-base-100)` on `:root`, and a custom property is resolved where it is declared. So under a nested `[data-theme="dark"]` (Storybook's ThemeFrame, or any themed section of an app), `--color-base-100` still carries the `:root` value. `--lux-*` is redeclared on the themed element itself. In luxoticars-dash, which has no `tokens.css`, `--lux-*` is undefined and daisyUI's variables, declared on the themed element, take over.
2. **`src/utils/dialog.js` (+ `.d.ts`)** is an internal module, not exported. It holds the option resolver and close icon both APIs use, so parity holds by construction rather than by review.
3. **`returnValue` is also reset on open.** The script clears it on `beforetoggle` (opening) as well as on `cancel`, so a dialog closed with the ✕ button or a backdrop click cannot report a stale value either.
4. **The Safari backdrop fallback checks where the pointer went down.** A text selection dragged from inside the dialog to the backdrop ends in a `click` on the dialog, and must not close it.
5. **Story-only files** `stories/ui/DialogDemo.astro` and `stories/dialog-content.ts` compose `Dialog` + `DialogTrigger` + `Button` the way an app does. A dialog without a trigger is invisible on a canvas.
6. **`tests/` + `npm test`** (`node:test`, zero dependencies) pin the builder's markup contract. CONTRIBUTING's "Testing" section is updated to say so.
7. **`DialogTrigger` forwards `Button`'s `left-icon` / `right-icon` slots.**
8. **`Dialog` also strips the `title` attribute.** A `title` attribute on `<dialog>` would add a tooltip that duplicates the `title` slot.
9. **Fallback behaviour is tested in Playwright WebKit**, which lacks `closedby` as Safari does. Chrome supports `closedby` natively, so a test there cannot tell the fallback from the platform.

## Review Focus

The five failure modes the spec implies but does not spell out, most likely first. Each has a test in the task named.

1. **A text selection dragged from inside a dialog onto the backdrop** must leave the dialog open, in Safari as well. → Task 3 "drag from inside to the backdrop does not close" (runs in Chrome and WebKit).
2. **Reopening after a footer choice, then dismissing with ✕, Escape or the backdrop**: `returnValue` must be `""`, not the previous choice. → Task 3 "confirm: Escape after a choice reports an empty result" and "lightbox: ✕ after a choice reports an empty result".
3. **An `id` containing whitespace or quote characters** (`"car 1"`, `x"><script>`) must fail loudly (whitespace) or be escaped (quotes), never produce a broken `aria-labelledby` / `commandfor` or break out of an attribute. → Task 1 "rejects invalid input with a message naming the dialog" (the `"car 1"` case) and "escapes title, description, closeLabel, className and id".
4. **Long content on a short phone viewport (375×600)**: the header and footer stay in view, only the body scrolls, and the page behind does not scroll. → Task 2 "long content" and "the page cannot scroll while a dialog is open".
5. **A dialog inside a nested `[data-theme="dark"]` while the OS is light**: the dialog must use the dark surface. The top layer does not break inheritance, and the token order (deviation 1) must hold. → Task 4 "dark subtree".

```ts
export type DialogVariant = "lightbox" | "confirm" | "panel";
```

Create `src/utils/dialog.js`:

```js
/*
  The one place a dialog's options are validated and turned into markup
  facts — classes, ids, role, `closedby`. `astro/ui/Dialog.astro` and
  `html/dialog.js` both call it, so the two APIs agree by construction rather
  than by being kept in step by hand. Internal: not in package.json#exports.
*/

const VARIANTS = ["lightbox", "confirm", "panel"];
const SIZES = ["narrow", "default", "wide", "large", "fullscreen"];
const SIDES = ["start", "end"];
const DISMISS = ["any", "closerequest", "none"];

/** Lucide "x". Decorative: the button carries the accessible name. */
export const DIALOG_CLOSE_ICON =
  '<svg class="dialog__close-icon" viewBox="0 0 24 24" width="16" height="16" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true" focusable="false"><path d="M18 6 6 18"/><path d="m6 6 12 12"/></svg>';

export function resolveDialogOptions({
  id,
  variant = "lightbox",
  size = "default",
  side = "start",
  dismiss,
  hasTitle,
  hasDescription,
}) {
  const named = typeof id === "string" && id.trim() !== "";
  const fail = (message) => {
    throw new Error(`Dialog${named ? ` "${id}"` : ""}: ${message}`);
  };

  if (!named) fail("an `id` is required — triggers target it, and the title and description ids derive from it.");
  /* An id with whitespace cannot be referenced by aria-labelledby or
     commandfor, both of which take space-separated id lists or single ids. */
  if (/\s/.test(id)) fail("the `id` cannot contain whitespace.");
  if (!VARIANTS.includes(variant)) fail(`unknown variant "${variant}". Use one of: ${VARIANTS.join(", ")}.`);
  if (!SIZES.includes(size)) fail(`unknown size "${size}". Use one of: ${SIZES.join(", ")}.`);
  if (!SIDES.includes(side)) fail(`unknown side "${side}". Use one of: ${SIDES.join(", ")}.`);
  if (size !== "default" && variant !== "lightbox") fail("`size` applies to the lightbox variant only.");
  if (side !== "start" && variant !== "panel") fail("`side` applies to the panel variant only.");

  const closedby = dismiss ?? (variant === "confirm" ? "closerequest" : "any");
  if (!DISMISS.includes(closedby)) fail(`unknown dismiss "${closedby}". Use one of: ${DISMISS.join(", ")}.`);
  if (variant === "confirm" && closedby === "any") {
    fail('a confirm cannot be dismissed by a backdrop click — use dismiss "closerequest" (the default) or "none".');
  }

  if (!hasTitle) fail("a title is required — it is the dialog's accessible name (the `title` slot, or the `title` option).");
  if (variant === "confirm" && !hasDescription) {
    fail("a confirm needs a description — it is what the alertdialog announces (the `description` slot, or the `description` option).");
  }

  return {
    classes: [
      "dialog",
      `dialog--${variant}`,
      variant === "lightbox" && size !== "default" && `dialog--${size}`,
      variant === "panel" && side === "end" && "dialog--end",
    ]
      .filter(Boolean)
      .join(" "),
    role: variant === "confirm" ? "alertdialog" : undefined,
    closedby,
    titleId: `${id}-title`,
    descriptionId: hasDescription ? `${id}-desc` : undefined,
    showClose: variant !== "confirm",
  };
}
```

Create `src/utils/dialog.d.ts`:

```ts
import type { DialogDismiss } from "../types";

export interface DialogOptionsInput {
  id: unknown;
  variant?: string;
  size?: string;
  side?: string;
  dismiss?: string;
  /** Whether a non-empty title was supplied (slot or option). */
  hasTitle: boolean;
  /** Whether a non-empty description was supplied (slot or option). */
  hasDescription: boolean;
}

export interface ResolvedDialog {
  /** BEM classes for the `<dialog>`, before any caller class is merged in. */
  classes: string;
  /** `alertdialog` for a confirm; `undefined` (the implicit `dialog`) otherwise. */
  role: "alertdialog" | undefined;
  closedby: DialogDismiss;
  titleId: string;
  /** Present only when a description was supplied. */
  descriptionId: string | undefined;
  /** Whether the header renders the ✕ button (never on a confirm). */
  showClose: boolean;
}

/**
 * Validates a dialog's options and derives its markup facts. Throws an
 * `Error` whose message starts `Dialog "<id>": `. Internal — shared by
 * `astro/ui/Dialog.astro` and `html/dialog.js`.
 */
export declare function resolveDialogOptions(input: DialogOptionsInput): ResolvedDialog;

/** The ✕ icon inside the close button. Decorative (`aria-hidden`). */
export declare const DIALOG_CLOSE_ICON: string;
```

- [ ] **Step 6: Write the builders**

Create `src/html/dialog.js`:

```js
import { escapeHtml, joinClasses } from "./utils.js";
import { createButton } from "./button.js";
import { DIALOG_CLOSE_ICON, resolveDialogOptions } from "../utils/dialog.js";

/*
  The HTML twin of `astro/ui/Dialog.astro`. Both emit the same tree, both get
  their classes, ids and role from `utils/dialog.js`, and both are styled by
  `styles/dialog.css` — which a caller of this builder loads itself, along
  with the runtime fallbacks:

      import "@luxoticars/ui/styles/dialog.css";
      import { installDialogFallbacks } from "@luxoticars/ui/scripts/dialog";
      installDialogFallbacks();
*/

const filled = (value) => typeof value === "string" && value.trim() !== "";

export const createDialog = ({
  id,
  variant,
  size,
  side,
  dismiss,
  closeLabel = "Close",
  title,
  description,
  body = "",
  footer = "",
  className = "",
} = {}) => {
  const d = resolveDialogOptions({
    id,
    variant,
    size,
    side,
    dismiss,
    hasTitle: filled(title),
    hasDescription: filled(description),
  });
  const eid = escapeHtml(id);

  const dialogAttributes = [
    `id="${eid}"`,
    `class="${escapeHtml(joinClasses(d.classes, className))}"`,
    d.role && `role="${d.role}"`,
    `aria-labelledby="${escapeHtml(d.titleId)}"`,
    d.descriptionId && `aria-describedby="${escapeHtml(d.descriptionId)}"`,
    `closedby="${d.closedby}"`,
  ]
    .filter(Boolean)
    .join(" ");

  const close = d.showClose
    ? `<button type="button" class="dialog__close" command="close" commandfor="${eid}" aria-label="${escapeHtml(closeLabel)}">${DIALOG_CLOSE_ICON}</button>`
    : "";
  const descriptionHtml = d.descriptionId
    ? `<div id="${escapeHtml(d.descriptionId)}" class="dialog__description">${escapeHtml(description)}</div>`
    : "";
  const bodyHtml = descriptionHtml || body ? `<div class="dialog__body">${descriptionHtml}${body}</div>` : "";
  const footerHtml = footer ? `<form method="dialog" class="dialog__footer">${footer}</form>` : "";

  return `<dialog ${dialogAttributes}><div class="dialog__header"><h2 id="${escapeHtml(d.titleId)}" class="dialog__title">${escapeHtml(title)}</h2>${close}</div>${bodyHtml}${footerHtml}</dialog>`;
};

/* Built on createButton so a trigger looks like every other HTML-API button;
   the two invoker attributes are spliced into its opening tag. */
export const createDialogTrigger = ({ for: target, label, className = "" } = {}) => {
  if (typeof target !== "string" || target.trim() === "" || /\s/.test(target)) {
    throw new Error("DialogTrigger: `for` must be the id of the dialog to open, with no whitespace.");
  }
  return createButton({ label, className }).replace(
    "<button ",
    `<button command="show-modal" commandfor="${escapeHtml(target)}" `,
  );
```

  /** Required. Triggers target it; `<id>-title` and `<id>-desc` derive from it. No whitespace. */
  id: string;
  /** Required. The accessible name, rendered as the `<h2>`. Escaped. */
  title: string;
  /** Rendered first in the body and referenced by `aria-describedby`. Escaped. */
  description?: string;
  /** Body HTML. **Not escaped** — trusted markup supplied by the caller. */
  body?: string;
  /**
   * Footer HTML, placed inside `<form method="dialog">`: a submit button there
   * closes the dialog and its `value` becomes `dialog.returnValue`.
   * **Not escaped** — trusted markup supplied by the caller.
   */
  footer?: string;
  /** Extra classes on the `<dialog>`. Escaped. */
  className?: string;
}

/** Options for {@link createDialog}, discriminated on `variant` like the Astro props. */
export type DialogOptions =
  | (DialogBase & {
      variant?: "lightbox";
      /** @default "default" (616px) */
      size?: DialogSize;
      side?: never;
      /** @default "any" */
      dismiss?: DialogDismiss;
      /** Accessible name of the ✕ button. Escaped. @default "Close" */
      closeLabel?: string;

      variant: "panel";

      side?: never;

```js
import { createServer } from "node:http";
import { readFile, stat } from "node:fs/promises";
import { extname, join, normalize } from "node:path";

/* The luxoticars-ui checkout. Set it when running the tests: REPO=/path/to/luxoticars-ui */
export const REPO = process.env.REPO;
if (!REPO) throw new Error("Set REPO to the root of the luxoticars-ui checkout.");

/* A local Chrome or Chromium; unset, Playwright uses its own Chromium build. */
const CHROME = process.env.CHROME_PATH;

const TYPES = {
  ".html": "text/html",
  ".js": "text/javascript",
  ".mjs": "text/javascript",
  ".css": "text/css",
  ".json": "application/json",
  ".svg": "image/svg+xml",
  ".png": "image/png",
  ".woff2": "font/woff2",
};

/** Serves a directory over HTTP on a free port. */
export function serveDir(root) {
  const server = createServer(async (req, res) => {
    const rel = normalize(decodeURIComponent(new URL(req.url, "http://x").pathname)).replace(/^(\.\.[/\\])+/, "");
    let file = join(root, rel);
    try {
      if ((await stat(file)).isDirectory()) file = join(file, "index.html");
      const body = await readFile(file);
      res.writeHead(200, { "content-type": TYPES[extname(file)] ?? "application/octet-stream" });
      res.end(body);
    } catch {
      res.writeHead(404);
      res.end();
    }
  });
  return new Promise((resolve) =>
    server.listen(0, "127.0.0.1", () => resolve({ server, url: `http://127.0.0.1:${server.address().port}` })),
  );
}

export const launch = (engine = "chromium") =>
  engine === "webkit" ? webkit.launch() : chromium.launch({ executablePath: CHROME });

export async function openStory(
  browser,
  base,
  id,
  { width = 1280, height = 800, colorScheme = "light", reducedMotion = "no-preference", init } = {},
) {
  const page = await browser.newPage({ viewport: { width, height }, colorScheme, reducedMotion });
  if (init) await page.addInitScript(init);
  await page.goto(`${base}/iframe.html?id=${id}&viewMode=story`);
  await page.locator("dialog.dialog").waitFor({ state: "attached" });
  return page;
}

/** Clicks the story's trigger and, by default, waits out the 500ms entry. */
export async function openDialog(page, { settle = true } = {}) {
  await page.locator("button[command=show-modal]").first().click();
  await page.locator("dialog.dialog[open]").waitFor();
  if (settle) await page.waitForTimeout(650);
}

export const box = (page, selector = "dialog.dialog") => page.locator(selector).boundingBox();
```

```css
      import "@luxoticars/ui/styles/dialog.css";
```

```js
/*
  Runtime fallbacks for `.dialog`. `Dialog.astro` installs them through a
  processed <script>, which Astro bundles once per page; HTML-API callers call
  `installDialogFallbacks()` themselves. Everything else a dialog does —
  opening, focus containment, Escape, focus return — is the platform's.

  Listeners are delegated to the document, so dialogs added after
  installation are covered, and installation is once per document.
*/

const installed = new WeakSet();
let pressedOnBackdrop = false;

const isDialog = (node) => node instanceof Element && node.matches("dialog.dialog");

/* Was the pointer on this dialog's backdrop? A click on ::backdrop is
   dispatched to the dialog itself, so the target is the dialog and the
   point lies outside its box. */
const onBackdrop = (event) => {
  const dialog = event.target;
  if (!isDialog(dialog) || !dialog.open) return false;
  const r = dialog.getBoundingClientRect();
  return event.clientX < r.left || event.clientX > r.right || event.clientY < r.top || event.clientY > r.bottom;
};

export function installDialogFallbacks(doc = globalThis.document) {
  if (!doc || installed.has(doc)) return;
  installed.add(doc);

  const nativeClosedBy = "closedBy" in doc.defaultView.HTMLDialogElement.prototype;

  /* returnValue survives a close that carries no value (Escape, the ✕
     command, a light dismiss), so a confirm closed with "delete", reopened
     and dismissed would still report "delete". Clear it when the dialog
     opens, and again when it is cancelled. */
  doc.addEventListener(
    "beforetoggle",
    (event) => {
      if (isDialog(event.target) && event.newState === "open") event.target.returnValue = "";
    },
    true,
  );

  doc.addEventListener(
    "cancel",
    (event) => {
      const dialog = event.target;
      if (!isDialog(dialog)) return;
      /* Safari has no closedby, so closedby="none" does not stop Escape there. */
      if (!nativeClosedBy && dialog.getAttribute("closedby") === "none") {
        event.preventDefault();
        return;
      }
      dialog.returnValue = "";
    },
    true,
  );

  if (nativeClosedBy) return;

  /* Safari: close a closedby="any" dialog on a backdrop click. Only when the
     press also started on the backdrop — a text selection dragged from inside
     the dialog ends in a click on the dialog too, and must not close it. */
  doc.addEventListener("pointerdown", (event) => {
    pressedOnBackdrop = onBackdrop(event);
  });
  doc.addEventListener("click", (event) => {
    const dialog = event.target;
    if (pressedOnBackdrop && onBackdrop(event) && dialog.getAttribute("closedby") === "any") {
      dialog.close("");
    }
    pressedOnBackdrop = false;
  });
}
```

```astro
import type { HTMLAttributes } from "astro/types";
import type { DialogDismiss, DialogSide, DialogSize } from "../../types";
import { cn } from "../../utils/cn.js";
import { DIALOG_CLOSE_ICON, resolveDialogOptions } from "../../utils/dialog.js";
/*
  Imported in the frontmatter, not through an `@import` in a scoped <style>,
  for the reason Logo.astro gives: Storybook's prerender would 404 it.
*/
import "../../styles/dialog.css";

/*
  Attributes the component derives itself. They are typed out here and
  removed from the spread below, because an HTML parser keeps the FIRST of a
  duplicated attribute — a caller's own value would silently win (see
  Button.astro). `open` shows the dialog non-modally, bypassing focus
  containment; `title` would add a tooltip duplicating the title slot.
*/
type Controlled = "id" | "role" | "aria-labelledby" | "aria-describedby" | "closedby" | "open" | "title";

interface Shared {
  /**
   * Required. A `DialogTrigger` targets it with `for`, and the title and
   * description ids derive from it (`<id>-title`, `<id>-desc`). No whitespace.
   */
  id: string;
}

interface Dismissible {
  /**
   * What may close the dialog besides its own buttons, mapped onto
   * `closedby`: `any` — Escape and a backdrop click; `closerequest` — Escape
   * only (use it for forms, so a stray click does not discard input);
   * `none` — neither.
   * @default "any"
   */
  dismiss?: DialogDismiss;
  /** Accessible name of the ✕ button. @default "Close" */
  closeLabel?: string;
}

export type Props = Omit<HTMLAttributes<"dialog">, Controlled> &
  Shared &
  (
    | (Dismissible & {
        /** A centred content dialog; a bottom sheet under 512px. @default "lightbox" */
        variant?: "lightbox";
        /** Width/height preset: 480 / 616 / 896px, `large` (70% tall) or `fullscreen` on a phone. @default "default" */
        size?: DialogSize;
        side?: never;
      })
    | (Dismissible & {
        /** A full-height side sheet, 384px wide from 512px. */
        variant: "panel";
        /** The edge it is attached to, in the writing direction. @default "start" */
        side?: DialogSide;
        size?: never;
      })
    | {
        /**
         * A forced choice: `role="alertdialog"`, no ✕, Escape cancels, a
         * backdrop click does nothing. Requires the `description` slot. Put
         * the safe action first in the footer — it receives focus.
         */
        variant: "confirm";
        /** @default "closerequest" */
        dismiss?: Exclude<DialogDismiss, "any">;
        size?: never;
        side?: never;
        closeLabel?: never;
      }
  );

/**
 * A modal dialog on the native `<dialog>` element: focus containment, an
 * inert page, Escape and focus return are the platform's.
 *
 * Slots: `title` (required — the accessible name), `description`
 * (required for `confirm`; announced via `aria-describedby`), default (the
 * body, which scrolls), `footer` (inside `<form method="dialog">`: a submit
 * button there closes the dialog, and its `value` becomes
 * `dialog.returnValue`).
 *
 * Open it with a `DialogTrigger for={id}`. To host a form, put the `<form
 * id>` in the body and give the footer's submit button `form={thatId}`.
 *
 * Styled by `styles/dialog.css` (imported here) and backed by
 * `scripts/dialog.js` (installed here), so nothing needs wiring up.
 */
const {
  id,
  variant,
  size,
  side,
  dismiss,
  closeLabel = "Close",
  class: className,
  ...attributes
} = Astro.props as Props & { size?: DialogSize; side?: DialogSide; closeLabel?: string };

/* Typed out of Props already; removed here too, because a caller in plain
   JS or behind a cast is not type-checked. The cast widens back to every
   <dialog> attribute so these keys can be named, and keeps `rest` typed for
   the spread. */
const {
  role: _role,
  "aria-labelledby": _labelledby,
  "aria-describedby": _describedby,
  closedby: _closedby,
  open: _open,
  title: _title,
  ...rest
} = attributes as HTMLAttributes<"dialog">;

const hasDescription = Astro.slots.has("description");
const d = resolveDialogOptions({
  id,
  variant,
  size,
  side,
  dismiss,
  hasTitle: Astro.slots.has("title"),
  hasDescription,
});
const hasBody = hasDescription || Astro.slots.has("default");
const hasFooter = Astro.slots.has("footer");
---

<dialog
  {...rest}
  id={id}
  class={cn(d.classes, className)}
  role={d.role}
  aria-labelledby={d.titleId}
  aria-describedby={d.descriptionId}
  closedby={d.closedby}
>
  <div class="dialog__header">
    <h2 id={d.titleId} class="dialog__title"><slot name="title" /></h2>
    {
      d.showClose && (
        <button
          type="button"
          class="dialog__close"
          command="close"
          commandfor={id}
          aria-label={closeLabel}
          set:html={DIALOG_CLOSE_ICON}
        />
      )
    }
  </div>
  {
    hasBody && (
      <div class="dialog__body">
        {hasDescription && (
          <div id={d.descriptionId} class="dialog__description">
            <slot name="description" />
          </div>
        )}
        <slot />
      </div>
    )
  }
  {
    hasFooter && (
      <form method="dialog" class="dialog__footer">
        <slot name="footer" />
      </form>
    )
  }
</dialog>

<script>
  import { installDialogFallbacks } from "../../scripts/dialog.js";
  installDialogFallbacks();
</script>
```
